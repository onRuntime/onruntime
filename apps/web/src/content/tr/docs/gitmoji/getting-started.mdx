We like to have a clean project history. Our commits convention is inspired by [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0) but customized with [gitmoji](https://gitmoji.dev) to make it more visual and fun.

## Yapı

Commit mesajı aşağıdaki gibi yapılandırılmalı ve **küçük harfle** yazılmalıdır:

```
<gitmoji> <type> <description> [(#<issue number>)]

[opsiyonel gövde]

[opsiyonel ayak (lar)]
```

### Örnek

```bash
📝 belgeleri güncelle
- @jerembdn katkıcı olarak ekle
- @younesbessa katkıcı olarak ekle

Co-authored-by: Younes Bessa <younes@onruntime.com>
```

Çoğu zaman, basit bir tek satır yeterlidir:

```bash
📝 belgeleri güncelle
```

## Türler

Aşağıdaki commit türlerini kullanıyoruz:

| Tür | Açıklama |
| --- | --- |
| `add` | Yeni bir özellik ekle |
| `fix` | Bir hatayı düzelt |
| `improve` | Bir şeyi geliştir |
| `update` | Bir şeyi güncelle |
| `remove` | Bir şeyi kaldır |
| `refactor` | Bir şeyi yeniden yapılandır |
| `rename` | Bir şeyi yeniden adlandır |
| `move` | Bir dosyayı veya klasörü taşı |
| `upgrade` | Bağımlılıkları güncelle |
| `downgrade` | Bağımlılıkları düşür |
| `initial` | Bir depodaki ilk commit |
| `release` | Sürüm / versiyon etiketi |

Bir reposunun ilk commit'i `initial` kullanırken, bir versiyon etiketi `release` kullanıyor:

```bash
🎉 ilk commit
🔖 release @onruntime/translations v0.3.0
```

## Açıklama

Açıklamaları **emir kipiyle** ve **küçük harfle** yazın:

```bash
# İyi
📝 belgeleri güncelle

# Kötü
📝 belgeleri güncelledi

# Kötü
📝 Belgeleri güncelle
```

## Issue Numarası

Commit'leri issue'lara bağlamak için issue numarasını ekleyin:

```bash
📝 belgeleri güncelle (#123)
```

## Gövde

Gövdeyi bağlam ve motivasyon için kullanın:

```bash
📝 belgeleri güncelle

- @jerembdn katkıcı olarak ekle
- @younesbessa katkıcı olarak ekle

Co-authored-by: Younes Bessa <younes@onruntime.com>
```

<Callout type="info" title="Bir Commit, Bir Amaç">
  Her commit tek bir mantıksal değişikliği temsil etmelidir. İlgisiz değişiklikleri birleştirmeyin.
</Callout>
