title: 시작하기
description: 우리의 커밋 규칙을 배워보세요
---
우리는 깔끔한 프로젝트 히스토리를 좋아해. 우리의 커밋 규칙은 [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0)에서 영감을 받았지만, 더 시각적이고 재미있게 만들기 위해 [gitmoji](https://gitmoji.dev)로 커스터마이즈했어.

## 구조

커밋 메시지는 다음과 같이 **소문자**로 구조화되어야 해:

```
<gitmoji> <type> <description> [(#<issue number>)]

[optional body]

[optional footer(s)]
```

### 예시

```bash
📝 update documentation contributors

- Add @jerembdn as a contributor
- Add @younesbessa as a contributor

Co-authored-by: Younes Bessa <younes@onruntime.com>
```

대부분의 경우, 간단한 한 줄이면 충분해:

```bash
📝 update documentation contributors
```

## 유형

우리는 다음의 커밋 유형을 사용해:

| Type | Description |
| --- | --- |
| `add` | 새로운 기능 추가 |
| `fix` | 버그 수정 |
| `improve` | 무언가 개선 |
| `update` | 무언가 업데이트 |
| `remove` | 무언가 제거 |
| `refactor` | 무언가 리팩토링 |
| `rename` | 무언가 이름 변경 |
| `move` | 파일이나 폴더 이동 |
| `upgrade` | 의존성 업그레이드 |
| `downgrade` | 의존성 다운그레이드 |
| `initial` | 레포지토리의 초기 커밋 |
| `release` | 릴리스 / 버전 태그 |

레포지토리의 첫 번째 커밋은 `initial`을 사용하고, 버전 태그는 `release`를 사용해:

```bash
🎉 initial commit
🔖 release @onruntime/translations v0.3.0
```

## 설명

설명을 **명령문**으로 작성하고 **소문자**로 해:

```bash
# 좋음
📝 update documentation contributors

# 나쁨
📝 updated documentation contributors

# 나쁨
📝 Update documentation contributors
```

## 이슈 번호

이슈 번호를 추가하여 커밋을 이슈에 연결해:

```bash
📝 update documentation contributors (#123)
```

## 본문

본문은 맥락과 동기를 설명하는 데 사용해:

```bash
📝 update documentation contributors

- Add @jerembdn as a contributor
- Add @younesbessa as a contributor

Co-authored-by: Younes Bessa <younes@onruntime.com>
```

<Callout type="info" title="하나의 커밋, 하나의 목적">
  각 커밋은 하나의 논리적인 변화를 나타내야 해. 관련 없는 변화는 섞지 마.
</Callout>
