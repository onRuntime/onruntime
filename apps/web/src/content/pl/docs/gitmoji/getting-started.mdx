Lubimy mieć czystą historię projektu. Nasza konwencja commitów jest inspirowana [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0), ale dostosowana z [gitmoji](https://gitmoji.dev), żeby była bardziej wizualna i zabawna.

## Struktura

Wiadomość o commicie powinna być ustrukturyzowana w następujący sposób i **ma być napisana małymi literami**:

```
<gitmoji> <type> <description> [(#<issue number>)]

[opcjonalne body]

[opcjonalne footer(y)]
```

### Przykład

```bash
📝 update documentation contributors

- Dodaj @jerembdn jako współtwórcę
- Dodaj @younesbessa jako współtwórcę

Co-authored-by: Younes Bessa <younes@onruntime.com>
```

W większości przypadków wystarczy prosta, jednozdaniowa wiadomość:

```bash
📝 update documentation contributors
```

## Typy

Używamy następujących typów commitów:

| Typ | Opis |
| --- | --- |
| `add` | Dodaj nową funkcję |
| `fix` | Popraw błąd |
| `improve` | Popraw coś |
| `update` | Zaktualizuj coś |
| `remove` | Usuń coś |
| `refactor` | Refaktoryzuj coś |
| `rename` | Zmień nazwę czegoś |
| `move` | Przenieś plik lub folder |
| `upgrade` | Zaktualizuj zależności |
| `downgrade` | Obniż wersję zależności |
| `initial` | Początkowy commit repozytorium |
| `release` | Wydanie / tag wersji |

Pierwszy commit repozytorium używa `initial`, a tag wersji używa
`release`:

```bash
🎉 initial commit
🔖 release @onruntime/translations v0.3.0
```

## Opis

Pisanie opisów w **trybie rozkazującym** i **małymi literami**:

```bash
# Dobrze
📝 update documentation contributors

# Źle
📝 updated documentation contributors

# Źle
📝 Update documentation contributors
```

## Numer problemu

Linkuj commity do problemów, dodając numer problemu:

```bash
📝 update documentation contributors (#123)
```

## Treść

Użyj treści do podania kontekstu i motywacji:

```bash
📝 update documentation contributors

- Dodaj @jerembdn jako współtwórcę
- Dodaj @younesbessa jako współtwórcę

Co-authored-by: Younes Bessa <younes@onruntime.com>
```

<Callout type="info" title="Jeden Commit, Jeden Cel">
  Każdy commit powinien reprezentować jedną logiczną zmianę. Nie mieszaj niezwiązanych zmian.
</Callout>
