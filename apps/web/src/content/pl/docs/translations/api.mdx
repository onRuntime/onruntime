## TranslationsProvider

Komponent dostarczający, który owrapuje twoją aplikację.

```tsx
import { TranslationsProvider } from "@onruntime/translations/react";

<TranslationsProvider
  locale="pl"
  locales={{ en, fr }}
  fallbackLocale="en"
>
  {children}
</TranslationsProvider>
```

### Props

| Prop | Typ | Wymagane | Opis |
|------|------|----------|-------------|
| `locale` | `string` | Tak | Aktualny aktywny język |
| `locales` | `Record<string, object>` | Tak | Obiekt zawierający wszystkie tłumaczenia językowe |
| `fallbackLocale` | `string` | Nie | Język zapasowy, gdy klucz jest brakujący |
| `children` | `ReactNode` | Tak | Podkomponenty |

## useTranslation

Hook do uzyskiwania dostępu do tłumaczeń w komponentach klienckich.

```tsx
const { t, locale, setLocale } = useTranslation("namespace");
```

### Parametry

| Parametr | Typ | Wymagane | Opis |
|-----------|------|----------|-------------|
| `namespace` | `string` | Tak | Przestrzeń nazw tłumaczenia do użycia |

### Zwraca

| Własność | Typ | Opis |
|----------|------|-------------|
| `t` | `(key: string, vars?: object) => string` | Funkcja tłumaczenia |
| `locale` | `string` | Aktualny język |
| `setLocale` | `(locale: string) => void` | Funkcja do zmiany języka |

### Przykład

```tsx
const { t, locale, setLocale } = useTranslation("common");

// Podstawowe użycie
t("greeting");  // "Cześć"

// Z zmiennymi
t("greeting_name", { name: "John" });  // "Cześć, John!"

// Zagnieżdżone klucze
t("nav.home");  // "Strona główna"

// Zmień język
setLocale("fr");
```

## getTranslation

Asynchroniczna funkcja do uzyskiwania dostępu do tłumaczeń w komponentach serwerowych (Next.js).

```tsx
const { t } = await getTranslation("namespace");
```

### Parametry

| Parametr | Typ | Wymagane | Opis |
|-----------|------|----------|-------------|
| `namespace` | `string` | Tak | Przestrzeń nazw tłumaczenia do użycia |

### Zwraca

| Własność | Typ | Opis |
|----------|------|-------------|
| `t` | `(key: string, vars?: object) => string` | Funkcja tłumaczenia |
| `locale` | `string` | Aktualny język |

### Przykład

```tsx
// Komponent serwerowy
export default async function Page() {
  const { t } = await getTranslation("common");

  return <h1>{t("title")}</h1>;
}
```

## Link Component

Komponent Link z uwzględnieniem języka dla Next.js.

```tsx
import { Link } from "@onruntime/translations/next";

<Link href="/about">O nas</Link>
```

### Props

Wszystkie propsy z komponentu `Link` w Next.js, plus:

| Prop | Typ | Domyślnie | Opis |
|------|------|---------|-------------|
| `locale` | `string` | Aktualny język | Nadpisuje język linku |

### Przykład

```tsx
// Używa aktualnego języka
<Link href="/about">O nas</Link>

// Wymusza konkretny język
<Link href="/about" locale="fr">À propos</Link>
```

## Funkcja Tłumaczenia (t)

Funkcja `t` jest używana do pobierania przetłumaczonych ciągów.

### Sygnatura

```tsx
t(key: string, variables?: Record<string, string | number>): string
```

### Parametry

| Parametr | Typ | Opis |
|-----------|------|-------------|
| `key` | `string` | Klucz tłumaczenia (obsługuje notację kropkową) |
| `variables` | `object` | Zmienne do interpolacji |

### Interpolacja Zmiennych

```json
{
  "greeting": "Cześć, {name}!",
  "items": "Masz {count} przedmiotów"
}
```

```tsx
t("greeting", { name: "Alice" });  // "Cześć, Alice!"
t("items", { count: 5 });          // "Masz 5 przedmiotów"
```

### Liczby mnogie

Liczba, która zmienia sformułowanie, przechodzi przez argument `plural` zamiast drugiego klucza:

```json
{
  "battles": "{count, plural, one {# walka} other {# walki}}"
}
```

```tsx
t("battles", { count: 1 });  // "1 walka"
t("battles", { count: 4 });  // "4 walki"
```

`#` oznacza liczbę. Gałąź jest wybierana przez `Intl.PluralRules` w czytanym języku, więc każdy język pisze swoje potrzebne gałęzie:

```json
{
  "battles": "{count, plural, one {# bitwa} few {# bitwy} many {# bitew} other {# bitew}}"
}
```

```tsx
t("battles", { count: 1 });  // "1 bitwa"
t("battles", { count: 3 });  // "3 bitwy"
t("battles", { count: 5 });  // "5 bitew"
```

Angielski i francuski potrzebują dwóch form, polski i rosyjski trzech, arabski sześciu, a japoński tylko jednej. Ręcznie napisany pary liczby pojedynczej/mnogiej nie mogą tego wyrazić: pisze formę od pięciu w górę na każdą liczbę powyżej dwóch.

Dokładne dopasowanie ma pierwszeństwo przed swoją kategorią, co jest sposobem, w jaki język mówi "żaden" bez twierdzenia, że to kategoria zerowa:

```json
{
  "messages": "{count, plural, =0 {Brak wiadomości} one {# wiadomość} other {# wiadomości}}"
}
```

### Wybór

`select` dopasowuje wartość tak, jak jest napisana i przechodzi do `other`. Nosi zgodność gramatyczną, gdy dane znają atrybut:

```json
{
  "invited": "{gender, select, f {Ona} m {On} other {Oni}} dołączył do zespołu"
}
```

```tsx
t("invited", { gender: "f" });  // "Ona dołączyła do zespołu"
t("invited", { gender: "x" });  // "Oni dołączyli do zespołu"
```

Atrybut nie może być pochodzony z samego słowa, więc przekaż go jako zmienną. Dla dynamicznej nazwy własnej lepiej jest użyć sformułowania, które nie potrzebuje w ogóle artykułu.

Gałęzie zagnieżdżają się, więc `select` może zawierać `plural`, a każda z nich może zawierać zwykłe zmienne.

Tylko `plural` i `select` są wspierane. Daty i liczby lepiej formatować za pomocą `Intl` w miejscu wywołania, gdzie znasz opcje, które chcesz.

### Zagnieżdżone Klucze

```json
{
  "user": {
    "profile": {
      "title": "Profil"
    }
  }
}
```

```tsx
t("user.profile.title");  // "Profil"
```

## Definicje Typów

### TranslationNamespaces

Rozszerz ten interfejs dla bezpiecznych typowo tłumaczeń:

```tsx
declare module "@onruntime/translations" {
  interface TranslationNamespaces {
    common: typeof import("./locales/pl/common.json");
    auth: typeof import("./locales/pl/auth.json");
  }
}
```

<Callout type="info" title="Zalety TypeScript">
  Dzięki odpowiednim definicjom typów, otrzymasz autouzupełnianie dla kluczy tłumaczeń i błędy kompilacji dla nieprawidłowych kluczy.
</Callout>
