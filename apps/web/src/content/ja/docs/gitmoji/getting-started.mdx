私たちはクリーンなプロジェクト履歴を持つのが好きです。私たちのコミット規約は [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0) に触発されていますが、もっと視覚的で楽しくするために [gitmoji](https://gitmoji.dev) でカスタマイズされています。

## 構造

コミットメッセージは以下のように構造化されていて、**小文字**で書くべきです：

```
<gitmoji> <type> <description> [(#<issue number>)]

[任意の本文]

[任意のフッター]
```

### 例

```bash
📝 update documentation contributors

- Add @jerembdn as a contributor
- Add @younesbessa as a contributor

Co-authored-by: Younes Bessa <younes@onruntime.com>
```

大抵の場合、シンプルなワンライナーで十分です：

```bash
📝 update documentation contributors
```

## タイプ

私たちは以下のコミットタイプを使用します：

| タイプ | 説明 |
| --- | --- |
| `add` | 新機能を追加 |
| `fix` | バグを修正 |
| `improve` | 何かを改善 |
| `update` | 何かを更新 |
| `remove` | 何かを削除 |
| `refactor` | 何かをリファクタリング |
| `rename` | 何かの名前を変更 |
| `move` | ファイルやフォルダーを移動 |
| `upgrade` | 依存関係をアップグレード |
| `downgrade` | 依存関係をダウングレード |
| `initial` | リポジトリの初期コミット |
| `release` | リリース / バージョンタグ |

リポジトリの最初のコミットは `initial` を使用し、バージョンタグは `release` を使います：

```bash
🎉 initial commit
🔖 release @onruntime/translations v0.3.0
```

## 説明

`<type>` は主語の動詞で、説明がそれを補完します。一緒に読むと、**一文**になります：

```bash
# Good
📝 update documentation contributors
```

だから、説明を第二の動詞で始めないでください。タイプはすでに一つあり、主語が二つの文を重ねてしまいます。これは `fix:` プレフィックスがもたらすものです。動詞を省いて、何に作用したのかを残してください：

```bash
# Bad
💄 improve scale down the gem on its card
🐛 fix stop the footer from wrapping

# Good
💄 improve the gem size on its card
🐛 fix the footer wrapping
```

**命令形** と **小文字** で書いてください：

```bash
# Bad
📝 updated documentation contributors

# Bad
📝 Update documentation contributors
```

<Callout type="info" title="名詞としての動詞">
  一部の単語は動詞と名詞の両方ですが、あなたが指しているのは名詞です： `✨ add open graph image` は大丈夫です。動詞として読むと、冠詞が名詞句に戻ります： `✨ add a show more button`。
</Callout>

## イシュー番号

コミットをイシューにリンクさせるには、イシュー番号を追加します：

```bash
📝 update documentation contributors (#123)
```

## 本文

本文はコンテキストと動機のために使用します：

```bash
📝 update documentation contributors

- Add @jerembdn as a contributor
- Add @younesbessa as a contributor

Co-authored-by: Younes Bessa <younes@onruntime.com>
```

<Callout type="info" title="一つのコミット、一つの目的">
  各コミットは単一の論理的変更を表すべきです。無関係な変更を混ぜるべきではありません。
</Callout>
