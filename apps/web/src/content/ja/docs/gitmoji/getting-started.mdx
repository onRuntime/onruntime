私たちはクリーンなプロジェクト履歴を大事にしています。私たちのコミット規約は[Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0)にインスパイアされていますが、より視覚的で楽しいものにするために[gitmoji](https://gitmoji.dev)でカスタマイズされています。

## 構造

コミットメッセージは以下のように構成され、**小文字**で書くべきです：

```
<gitmoji> <type> <description> [(#<issue number>)]

[optional body]

[optional footer(s)]
```

### 例

```bash
📝 update documentation contributors

- @jerembdnを貢献者として追加
- @younesbessaを貢献者として追加

Co-authored-by: Younes Bessa <younes@onruntime.com>
```

ほとんどの場合、シンプルなワンライナーで十分です：

```bash
📝 update documentation contributors
```

## タイプ

私たちは以下のコミットタイプを使用しています：

| タイプ | 説明 |
| --- | --- |
| `add` | 新機能を追加 |
| `fix` | バグを修正 |
| `improve` | 何かを改善 |
| `update` | 何かを更新 |
| `remove` | 何かを削除 |
| `refactor` | 何かをリファクタリング |
| `rename` | 何かの名前を変更 |
| `move` | ファイルやフォルダーを移動 |
| `upgrade` | 依存関係をアップグレード |
| `downgrade` | 依存関係をダウングレード |
| `initial` | リポジトリの初回コミット |
| `release` | リリース / バージョンタグ |

リポジトリの最初のコミットでは`initial`を使用し、バージョンタグでは`release`を使用します：

```bash
🎉 initial commit
🔖 release @onruntime/translations v0.3.0
```

## 説明

説明は**命令形**かつ**小文字**で書いてください：

```bash
# 良い
📝 update documentation contributors

# 悪い
📝 updated documentation contributors

# 悪い
📝 Update documentation contributors
```

## イシュー番号

コミットにイシュー番号を追加して関連付けます：

```bash
📝 update documentation contributors (#123)
```

## 本文

本文はコンテキストとモチベーションのために使ってください：

```bash
📝 update documentation contributors

- @jerembdnを貢献者として追加
- @younesbessaを貢献者として追加

Co-authored-by: Younes Bessa <younes@onruntime.com>
```

<Callout type="info" title="一つのコミット、一つの目的">
  各コミットは単一の論理的変更を表すべきです。無関係な変更を混ぜないでください。
</Callout>
