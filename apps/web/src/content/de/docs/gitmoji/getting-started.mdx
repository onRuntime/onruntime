Wir mögen einen sauberen Projektverlauf. Unser Commit-Konvention ist inspiriert von [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0), aber mit [gitmoji](https://gitmoji.dev) angepasst, um es visuell und spaßig zu machen.

## Struktur

Die Commit-Nachricht sollte wie folgt strukturiert sein und **in Kleinbuchstaben**:

```
<gitmoji> <type> <beschreibung> [(#<issue nummer>)]

[optionale nachricht]

[optionale fußzeile(n)]
```

### Beispiel

```bash
📝 aktualisiere dokumentation mit beiträgen

- Füge @jerembdn als beitragenden hinzu
- Füge @younesbessa als beitragenden hinzu

Co-authored-by: Younes Bessa <younes@onruntime.com>
```

Meistens reicht eine einfache Zeile aus:

```bash
📝 aktualisiere dokumentation mit beiträgen
```

## Typen

Wir verwenden die folgenden Commit-Typen:

| Typ | Beschreibung |
| --- | --- |
| `add` | Füge ein neues Feature hinzu |
| `fix` | Behebe einen Fehler |
| `improve` | Verbessere etwas |
| `update` | Aktualisiere etwas |
| `remove` | Entferne etwas |
| `refactor` | Überarbeite etwas |
| `rename` | Benenne etwas um |
| `move` | Verschiebe eine Datei oder einen Ordner |
| `upgrade` | Update Abhängigkeiten |
| `downgrade` | Downgrade Abhängigkeiten |
| `initial` | Erster Commit eines Repositories |
| `release` | Release / Versions-Tag |

Der erste Commit eines Repositories verwendet `initial`, und ein Versions-Tag verwendet
`release`:

```bash
🎉 erster commit
🔖 release @onruntime/translations v0.3.0
```

## Beschreibung

Schreibe Beschreibungen im **Imperativ** und **klein geschrieben**:

```bash
# Gut
📝 aktualisiere dokumentation mit beiträgen

# Schlecht
📝 aktualisierte dokumentation mit beiträgen

# Schlecht
📝 Aktualisiere dokumentation mit beiträgen
```

## Issue Nummer

Verlinke Commits mit Issues, indem du die Issue-Nummer hinzufügst:

```bash
📝 aktualisiere dokumentation mit beiträgen (#123)
```

## Body

Verwende den Body für Kontext und Motivation:

```bash
📝 aktualisiere dokumentation mit beiträgen

- Füge @jerembdn als beitragenden hinzu
- Füge @younesbessa als beitragenden hinzu

Co-authored-by: Younes Bessa <younes@onruntime.com>
```

<Callout type="info" title="Ein Commit, Ein Zweck">
  Jeder Commit sollte eine einzelne logische Änderung repräsentieren. Misch keine unrelated changes.
</Callout>
