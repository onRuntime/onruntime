---
Vogliamo avere una cronologia del progetto pulita. La nostra convenzione sui commit è ispirata da [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0) ma personalizzata con [gitmoji](https://gitmoji.dev) per renderla più visiva e divertente.

## Struttura

Il messaggio del commit dovrebbe essere strutturato come segue e **in minuscolo**:

```
<gitmoji> <tipo> <descrizione> [(#<numero dell'issue>)]

[corpo facoltativo]

[footer(e) facoltativi]
```

### Esempio

```bash
📝 aggiorna i contributori della documentazione

- Aggiungi @jerembdn come contributore
- Aggiungi @younesbessa come contributore

Co-authored-by: Younes Bessa <younes@onruntime.com>
```

Nella maggior parte dei casi, una semplice riga è sufficiente:

```bash
📝 aggiorna i contributori della documentazione
```

## Tipi

Usiamo i seguenti tipi di commit:

| Tipo | Descrizione |
| --- | --- |
| `add` | Aggiungi una nuova funzionalità |
| `fix` | Correggi un bug |
| `improve` | Migliora qualcosa |
| `update` | Aggiorna qualcosa |
| `remove` | Rimuovi qualcosa |
| `refactor` | Rifattorizza qualcosa |
| `rename` | Rinomina qualcosa |
| `move` | Sposta un file o una cartella |
| `upgrade` | Aggiorna le dipendenze |
| `downgrade` | Downgrada le dipendenze |
| `initial` | Commit iniziale di un repository |
| `release` | Rilascio / tag di versione |

Il primo commit di un repository usa `initial`, e un tag di versione usa
`release`:

```bash
🎉 commit iniziale
🔖 rilascio @onruntime/translations v0.3.0
```

## Descrizione

Il `<tipo>` è il verbo del soggetto, e la descrizione lo completa. Letti insieme, formano **una frase**:

```bash
# Buono
📝 aggiorna i contributori della documentazione
```

Quindi non aprire la descrizione con un secondo verbo. Il tipo è già uno, e
il soggetto finisce per accumulare due frasi, che è ciò che porta un prefisso `fix:`. Elimina il verbo e mantieni ciò su cui ha agito:

```bash
# Cattivo
💄 migliora riduci la gemma sulla sua scheda
🐛 correggi fermati per evitare che il footer si avvolga

# Buono
💄 migliora la dimensione della gemma sulla sua scheda
🐛 correggi il footer che si avvolge
```

Scrivilo in **modo imperativo** e **minuscolo**:

```bash
# Cattivo
📝 aggiornato i contributori della documentazione

# Cattivo
📝 Aggiorna i contributori della documentazione
```

<Callout type="info" title="Un Verbo Che È un Sostantivo">
  Alcune parole sono entrambe, e quella che intendi è il sostantivo: `✨ add open graph image`
  va bene. Quando si legge come un verbo, un articolo lo rende di nuovo un'espressione nominale:
  `✨ add a show more button`.
</Callout>

## Numero dell'Issue

Collega i commit alle issue aggiungendo il numero dell'issue:

```bash
📝 aggiorna i contributori della documentazione (#123)
```

## Corpo

Usa il corpo per fornire contesto e motivazione:

```bash
📝 aggiorna i contributori della documentazione

- Aggiungi @jerembdn come contributore
- Aggiungi @younesbessa come contributore

Co-authored-by: Younes Bessa <younes@onruntime.com>
```

<Callout type="info" title="Un Commit, Un Scopo">
  Ogni commit dovrebbe rappresentare una singola modifica logica. Non mescolare modifiche non correlate.
</Callout>
