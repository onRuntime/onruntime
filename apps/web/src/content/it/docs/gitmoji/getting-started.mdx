Ci piace avere una storia di progetto pulita. La nostra convenzione sui commit è ispirata da [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0) ma personalizzata con [gitmoji](https://gitmoji.dev) per renderla più visiva e divertente.

## Struttura

Il messaggio del commit dovrebbe essere strutturato come segue e **in minuscolo**:

```
<gitmoji> <type> <description> [(#<issue number>)]

[corpo opzionale]

[footer(s) opzionale(i)]
```

### Esempio

```bash
📝 update documentation contributors

- Add @jerembdn as a contributor
- Add @younesbessa as a contributor

Co-authored-by: Younes Bessa <younes@onruntime.com>
```

La maggior parte delle volte, una semplice riga è sufficiente:

```bash
📝 update documentation contributors
```

## Tipi

Utilizziamo i seguenti tipi di commit:

| Tipo | Descrizione |
| --- | --- |
| `add` | Aggiungi una nuova funzionalità |
| `fix` | Risolvi un bug |
| `improve` | Migliora qualcosa |
| `update` | Aggiorna qualcosa |
| `remove` | Rimuovi qualcosa |
| `refactor` | Rifattorizza qualcosa |
| `rename` | Rinomina qualcosa |
| `move` | Sposta un file o una cartella |
| `upgrade` | Aggiorna le dipendenze |
| `downgrade` | Riduci le dipendenze |
| `initial` | Commit iniziale di un repository |
| `release` | Rilascia / tag versione |

Il primo commit di un repository utilizza `initial`, e un tag di versione utilizza `release`:

```bash
🎉 initial commit
🔖 release @onruntime/translations v0.3.0
```

## Descrizione

Scrivi le descrizioni in **modo imperativo** e **in minuscolo**:

```bash
# Buono
📝 update documentation contributors

# Cattivo
📝 updated documentation contributors

# Cattivo
📝 Update documentation contributors
```

## Numero dell'Issue

Collega i commit alle issues aggiungendo il numero dell'issue:

```bash
📝 update documentation contributors (#123)
```

## Corpo

Usa il corpo per il contesto e la motivazione:

```bash
📝 update documentation contributors

- Add @jerembdn as a contributor
- Add @younesbessa as a contributor

Co-authored-by: Younes Bessa <younes@onruntime.com>
```

<Callout type="info" title="Un Commit, Un Obiettivo">
  Ogni commit dovrebbe rappresentare un singolo cambiamento logico. Non mescolare cambiamenti non correlati.
</Callout>
