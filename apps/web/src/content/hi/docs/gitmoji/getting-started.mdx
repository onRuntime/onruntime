हम एक साफ परियोजना इतिहास रखना पसंद करते हैं। हमारे कमिट का नियम [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0) से प्रेरित है लेकिन इसे [gitmoji](https://gitmoji.dev) के साथ कस्टमाइज़ किया गया है ताकि इसे और अधिक दृश्य और मजेदार बनाया जा सके।

## संरचना

कमिट संदेश को इस प्रकार से संरचना दी जानी चाहिए और **छोटे अक्षरों में**:

```
<gitmoji> <type> <description> [(#<issue number>)]

[optional body]

[optional footer(s)]
```

### उदाहरण

```bash
📝 update documentation contributors

- Add @jerembdn as a contributor
- Add @younesbessa as a contributor

Co-authored-by: Younes Bessa <younes@onruntime.com>
```

ज़्यादातर समय, एक साधारण एक-लाइनर ही काफी है:

```bash
📝 update documentation contributors
```

## प्रकार

हम निम्नलिखित कमिट प्रकारों का उपयोग करते हैं:

| प्रकार | विवरण |
| --- | --- |
| `add` | एक नई विशेषता जोड़ें |
| `fix` | एक बग ठीक करें |
| `improve` | कुछ सुधारें |
| `update` | कुछ अपडेट करें |
| `remove` | कुछ हटा दें |
| `refactor` | कुछ को फिर से व्यवस्थित करें |
| `rename` | कुछ का नाम बदलें |
| `move` | एक फ़ाइल या फ़ोल्डर स्थानांतरित करें |
| `upgrade` | निर्भरताओं को अपडेट करें |
| `downgrade` | निर्भरताओं को डाउनग्रेड करें |
| `initial` | एक रिपॉजिटरी का प्रारंभिक कमिट |
| `release` | रिलीज / संस्करण टैग |

रिपॉजिटरी का पहला कमिट `initial` का उपयोग करता है, और एक संस्करण टैग का उपयोग
`release` करता है:

```bash
🎉 initial commit
🔖 release @onruntime/translations v0.3.0
```

## विवरण

विवरण **आदेशात्मक शैली** और **छोटे अक्षरों में** लिखें:

```bash
# अच्छा
📝 update documentation contributors

# बुरा
📝 updated documentation contributors

# बुरा
📝 Update documentation contributors
```

## समस्या संख्या

कमिट्स को समस्याओं से जोड़ने के लिए समस्या संख्या जोड़ें:

```bash
📝 update documentation contributors (#123)
```

## शरीर

संदर्भ और प्रेरणा के लिए शरीर का उपयोग करें:

```bash
📝 update documentation contributors

- Add @jerembdn as a contributor
- Add @younesbessa as a contributor

Co-authored-by: Younes Bessa <younes@onruntime.com>
```

<Callout type="info" title="एक कमिट, एक उद्देश्य">
  प्रत्येक कमिट को एकल तार्किक परिवर्तन का प्रतिनिधित्व करना चाहिए। असंबंधित परिवर्तनों को मिश्रित न करें।
</Callout>
