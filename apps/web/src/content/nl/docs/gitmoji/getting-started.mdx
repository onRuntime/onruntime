We houden van een schone projectgeschiedenis. Onze commitconventie is geïnspireerd door [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0) maar aangepast met [gitmoji](https://gitmoji.dev) om het visueler en leuker te maken.

## Structuur

De commitboodschap moet als volgt gestructureerd zijn en **in kleine letters**:

```
<gitmoji> <type> <description> [(#<issue nummer>)]

[optioneel body]

[optionele footer(s)]
```

### Voorbeeld

```bash
📝 update documentatie bijdragers

- Voeg @jerembdn toe als bijdrager
- Voeg @younesbessa toe als bijdrager

Co-authored-by: Younes Bessa <younes@onruntime.com>
```

De meeste tijd is een simpele oneliner genoeg:

```bash
📝 update documentatie bijdragers
```

## Types

We gebruiken de volgende commit types:

| Type | Beschrijving |
| --- | --- |
| `add` | Voeg een nieuwe functie toe |
| `fix` | Los een bug op |
| `improve` | Verbeter iets |
| `update` | Update iets |
| `remove` | Verwijder iets |
| `refactor` | Refactor iets |
| `rename` | Hernoem iets |
| `move` | Verplaats een bestand of map |
| `upgrade` | Upgrade afhankelijkheden |
| `downgrade` | Downgrade afhankelijkheden |
| `initial` | Initiële commit van een repository |
| `release` | Release / versie tag |

De eerste commit van een repository gebruikt `initial`, en een versie tag
gebruikt `release`:

```bash
🎉 initiële commit
🔖 release @onruntime/translations v0.3.0
```

## Beschrijving

De `<type>` is het werkwoord van het onderwerp, en de beschrijving maakt het compleet. Samen vormen ze **één zin**:

```bash
# Goed
📝 update documentatie bijdragers
```

Dus begin de beschrijving niet met een tweede werkwoord. Het type is er al een, en het onderwerp leidt tot het stapelen van twee zinnen, wat een `fix:` prefix met zich meebrengt. Laat het werkwoord weg en behoud wat er op werd gewerkt:

```bash
# Slecht
💄 verbeter schalen van de juweel op zijn kaart
🐛 fix stop de footer van inpakken

# Goed
💄 verbeter de juweelgrootte op zijn kaart
🐛 fix het inpakken van de footer
```

Schrijf het in **imperatieve wijs** en **kleine letters**:

```bash
# Slecht
📝 bijgewerkt documentatie bijdragers

# Slecht
📝 Update documentatie bijdragers
```

<Callout type="info" title="Een Werkwoord Dat Een Zelfstandig Naamwoord Is">
  Sommige woorden zijn beide, en degene die je bedoelt, is het zelfstandige naamwoord: `✨ voeg afbeelding voor open graph toe`
  is prima. Wanneer het als een werkwoord gelezen wordt, maakt een lidwoord het weer tot een zelfstandige naamwoordgroep:  
  `✨ voeg een 'meer tonen' knop toe`.
</Callout>

## Issue Nummer

Koppel commits aan issues door het issue nummer toe te voegen:

```bash
📝 update documentatie bijdragers (#123)
```

## Body

Gebruik het bodygedeelte voor context en motivatie:

```bash
📝 update documentatie bijdragers

- Voeg @jerembdn toe als bijdrager
- Voeg @younesbessa toe als bijdrager

Co-authored-by: Younes Bessa <younes@onruntime.com>
```

<Callout type="info" title="Één Commit, Één Doel">
  Elke commit moet een enkele logische verandering vertegenwoordigen. Meng geen niet-verwante veranderingen.
</Callout>
